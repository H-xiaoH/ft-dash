# 界面数量设置与全自动重试

**日期：** 2026-10-30  
**状态：** 已实施  
**范围：** 设置页「界面」卡片、连接与保存前的探测、401 的处理、K 线/推送/轮询的重试策略

## 目标

操作者提出的四件事：总览两处列表的长度要能调；交易页每页条数要能调（含一页显示全部）；不要手动重试按钮；登录时先确认机器人可用再保存。

## 决定与理由

### 界面卡片（`settings.display`）

| 设置 | 标识符 | 默认 | 范围 |
| --- | --- | --- | --- |
| 总览：当前持仓上限 | `dashboardOpenLimit` | 6 | 1–50 |
| 总览：最近平仓上限 | `dashboardClosedLimit` | 6 | 1–50 |
| 交易页：每页条数 | `tradesPerPage` | 20 | 5–300 |

- 上限取 **300**，因为 `/trades?limit=300` 是应用一次加载的条数：300 就等于一页显示全部，不需要再造一个「不限」状态去解释和测试。
- 输入框绑原始值（打字期间可以是空串 / 0），视图读的是夹紧后的派生值 `overviewOpenLimit`、`overviewClosedLimit`、`tradesPageSize`。夹紧放在「读」而不是「写」，否则清空输入框重输时字段会被强行改写。
- 区间、默认值只写在 `COUNT_SETTINGS` 一处，输入框的 `min`/`max`、加载时的迁移、读取时的夹紧都引用它。
- 统计页的交易对表格**不跟随**这个设置，仍是固定的每页 10 条：它列的是交易对汇总，和交易流水不是同一种数据，共用一个数字只会让两边都不合适。

### 登录与保存前先探测

- 连接页：`ping` + `show_config` 通过后才写 `ftdash.bots.v1`、才切到主界面。密码错不会在列表里留下坏条目，也不会进入一个拉不到数据的空壳。
- 设置页「添加机器人」同样先探测；「编辑」在地址 / 用户名 / 密码变化时也探测，纯改名或改 ws_token 不探测（否则机器人离线时连改名都存不了）。机器人离线时无法保存这件事写在编辑器里（`bots.probeHint`）。

### 401 回登录页

401 在自动改用 Basic 重试后仍然失败，就不是抖动：轮询停止，应用回到连接表单（机器人列表与输入内容保留），提示条不再出现——壳里没有任何东西能修密码。实时推送同时关闭，避免带着旧 JWT 的 socket 在登录页背后继续推事件。

### 重试全部自动，不留按钮

| 失败 | 节奏 | 上限 |
| --- | --- | --- |
| 核心轮询（5xx / 网络） | 1 秒 | 无 |
| K 线请求 | 10 秒（停留在市场页时） | 无 |
| 推送握手被拒 / 无法启动 | 60 秒 | 无 |
| 断线后的推送（机器人为离线） | 连接恢复的那一刻 | 无 |

- 提示条只说明状态与「正在自动重试」，没有按钮。
- 推送「三次失败后停止」的旧行为取消：改为放慢到 60 秒一拍，机器人侧修好后自行恢复。
- 推送 socket 在机器人不可达期间断开时，重连计时器无法排（`connection !== 'online'`），因此记一个「欠一次重连」的标记，连接恢复时补上。

## 验证

- `tests/interface-limits.spec.ts`：默认值、持久化、加载时夹紧、读取时夹紧、300 上限。
- `tests/bot-session.spec.ts`：401 停止轮询；5xx 继续轮询。
- `tests/market-view.spec.ts`：K 线失败后 10 秒自动重试，成功后停止。
- `tests/bot-switch.spec.ts`：三次握手被拒后 60 秒自动重试；机器人恢复后推送自行复活。
- `tests/global-notices.spec.ts`：提示条没有任何按钮，文案说明会自动重试。
- `tests/bots-panel.spec.ts` / `e2e/smoke.spec.ts`：探测失败不保存、不连接；通过后才落盘。
- `e2e/smoke.spec.ts`：会话被拒后回到连接页；掉线的提示条说明会自动重试且无按钮。
