# 交易列表在手机上也能排序

**日期：** 2026-10-30
**状态：** 已实施
**范围：** 交易页工具条（手机宽度）

## 问题

排序逻辑本来就是共用的：`sortKey` / `sortDir`、`toggleSort()`、`rows` 的排序、以及「换排序回第一页」的 watcher。手机上排不了序，唯一原因是入口长在 `u-desktop-only` 表格的列头里。

## 验收标准

- 只要卡片列表取代了列头（`≤900px`，与 `.u-desktop-only` 同一个断点）工具条就多出两个控件：**排序**下拉（交易对 / 投入 / 盈亏 / 持仓时长 / 开仓时间）与**方向**按钮（`chevronUp` / `chevronDown`）。按钮的名字说动作，例如当前是降序就写「改为升序」——读屏用户听到的是按下去会发生什么，而不是当前状态。
- `>900px` 时这两个控件隐藏，桌面继续用列头排序，行为不变。不要用 `u-inline-sm`——它是 720px 断点，720–900 这段会出现「有卡片、没列头、也没排序入口」的空档。
- 选字段走 `toggleSort()`，方向规则与列头一致（交易对升序，其余降序）；方向按钮只翻转，不重开菜单。
- 排序作用于已加载的数据（≤300 条），不新增请求；换排序回到第一页（沿用现有 watcher）。
- 工具条不产生横向溢出：放不下时整行换行（`flex-wrap`）而不是把控件挤出屏幕；`≤720px` 间距收紧到 4px，这样 390px 的窄屏能保持一行；导出按钮在手机只留图标（`aria-label` 与 `title` 仍是「导出 CSV」）。
- 中英文案同步（`trades.sort` / `trades.sortAsc` / `trades.sortDesc`）。

## 不做什么

- 不改统计页、市场页的排序（统计页的每对表格有同样的缺口，需要时按同一套做法再做一次）。
- 不加「点同一项换个方向」这种隐藏手势，方向始终可见。
- 不动服务端排序或接口参数。
