# 数据独立刷新

- 全量刷新同时启动核心、交易历史、统计、市场和系统资源，各接口返回即写入；最终汇总继续等待全部完成。
- 前台轮询按原有 1/4/12 秒频率独立调度各组。正在请求的组跳过本组重复轮询，其他组不受影响；旧请求完成不能释放新会话的轮询锁。
- 后台仍只按原条件检查健康，切页 300ms 合并等待保持。
- 保留 epoch、请求代次、过期响应丢弃、快照有效性和写操作门禁。心跳未完成时可以显示其他资源，但不会提前把核心数据标为就绪。
- 组错误和连接错误优先保留鉴权失败；晚到的成功响应不能清除另一必要资源的鉴权错误；连接收尾与常规刷新共用相同的传输错误优先级。核心网络恢复仍可恢复在线状态，历史资源就绪状态继续独立限制写操作。
- 回归测试覆盖心跳未完成时其他资源可用、慢核心组不拖住其他轮询、混合网络/鉴权失败不被历史成功覆盖；既有机器人切换和连接恢复测试继续执行。
