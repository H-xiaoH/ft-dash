# 交易界面与交互一致性设计

**日期：** 2026-10-28  
**状态：** 已实施并合并  
**范围：** 交易、总览、市场、日志、设置的手势、滚动边界与提示一致性

## 目标

优化 `ft-dash` 的交易、总览、市场、日志和设置体验，重点解决移动端手势与滚动边界、交易详情返回语义、设置控件一致性，以及破坏性操作提示的视觉一致性。

这次改动不改变 Freqtrade API 合同、数据模型或机器人轮询策略；只调整前端路由状态、展示和交互。

## 术语与约束

- 使用 `CONTEXT.md` 中的领域词汇：`pair` 表示交易对，`trade` 表示交易，`openTrades` 表示当前持仓，`closedTrades` 表示已平仓，`bot` 表示机器人，底部通知称为提示条。
- 项目是 Vue 3 + TypeScript + Composition API + Vue Router 的独立 PWA，不使用 Laravel/Inertia/Wayfinder，也不引入 shadcn-vue 或新的图标库。
- 保留现有 `FilterMenu`、`ConfirmDialog`、`AppIcon` 和全局 token/CSS 体系；新增抽象只有在至少两个现有区域复用时才引入。
- 中文和英文文案必须同步维护。

## 用户行为设计

### 1. 交易筛选与交易详情

- `交易`页的三个筛选仍使用 `open | closed | all`，默认 `all`；桌面继续支持点击。
- 三个筛选控件仅通过点击切换；交易页不消费左右手势，横向手势继续交给全局页面导航或原生横向滚动容器。
- 总览“当前持仓”表格行进入 `/trades` 时带 `filter=open` 与对应 `trade` query；“最近平仓”表格行带 `filter=closed` 与对应 `trade` query。总览的“查看全部”入口继续只带筛选 query。
- 从交易列表打开详情时用新的历史项保存 `trade` query；详情关闭按钮移除 `trade` query，保留 `filter` 和列表所在页面。
- 交易 query 被浏览器/系统返回移除时，详情抽屉必须关闭，不能残留已选择的交易。外部深链直接进入详情时，关闭按钮使用 replace 清理 query，避免产生多余历史项。
- `TradeDetail` 继续作为桌面右侧抽屉、移动端底部抽屉；“返回/关闭”语义是关闭交易详情，不是离开交易页。

### 2. 交易详情的移动端滚动

- 详情打开时主壳保持 `inert`，并锁定 `body` 滚动；详情正文是唯一纵向滚动容器。
- 详情正文到达顶部或底部时禁止滚动链传递到主页面，避免继续滑动导致主页面移动。
- 全局弹层焦点/滚动锁需要支持交易详情与确认框短暂嵌套：只有最后一个弹层关闭后才解除 `inert` 和 body 滚动锁。
- 确认框也要继承同一套滚动锁行为，但不改变强制平仓所需的文字确认逻辑。

### 3. 设置与机器人

- 设置中的“语言”和“时区”都使用同一个 `FilterMenu` 外观、对齐方式、按钮宽度和字段布局；时区继续保留搜索和时区偏移提示，语言不强行增加无必要的搜索。
- 机器人测试成功后，原“测试连接”按钮本身变为“连接成功”的成功态；名称区域不再显示重复的成功 chip。测试失败保留可再次测试的操作入口。
- 设置中添加机器人时，用户名输入会在机器人名称仍未被手动编辑时实时补充名称；一旦操作者编辑名称则停止自动覆盖。编辑已有机器人时保留已有名称。
- 删除机器人取消弹窗，改为机器人列表下方的内联确认提示，视觉和按钮排列复用“清除本机数据”的确认提示；确认成功/失败仍使用现有提示条。

### 4. 日志、提示条与市场列表

- 日志时间显示为日期与时间两行（视觉等价于日期后换行），不改变当前 `timezone` 偏好和 locale 格式化。
- 提示条宽度按内容自适应，在窄屏上仍受视口边距和最大宽度限制；长文案允许换行，不让提示条撑出视口。
- 市场页的交易对名单不再使用固定 `62vh` 上限。市场页在视口可用高度内使用 flex 布局：K 线区域保留自身内容，交易对名单占用剩余空间，名单内部滚动，主页面不因名单长度滚动。
- 审查现有同类交互：共享弹层焦点/滚动锁、共用提示条宽度和内联确认布局一并修复；需要文字确认或风险确认的操作（例如强制平仓）继续保留确认框。

### 新增共享组件

新增 `src/components/InlineConfirm.vue`，职责是渲染一个非模态、可换行、居中的确认提示。

- Props：`open`、`message`、`confirmLabel`、`cancelLabel`、`pending`。
- Emits：`confirm`、`cancel`。
- 只负责展示和事件上抛，不持有业务状态；机器人删除和清除本机数据各自决定何时打开、确认后调用什么动作。

## 路由与状态边界

```text
总览当前持仓行 ── filter=open + trade=id ──┐
总览最近平仓行 ── filter=closed + trade=id ─┤
交易列表行 ───── filter(现有) + trade=id ──┘
                         ↓
              TradesView 解析 query
              filter → 列表筛选
              trade  → 交易抽屉
                         ↓ 关闭/返回
              只移除 trade，保留 filter
```

- `filter` 是列表视图状态，`trade` 是抽屉状态；二者不能互相推断或混用。
- 机器人切换时沿用已有边界，清除筛选和交易详情 query，避免新机器人继承旧数据源的页面状态。
- 日期/时间格式化继续从 `useFormat` 读取 `settings.timezone` 和当前 `locale`，不在日志页重复解析时区。

## 验收标准

### 交易与滚动

- 手机上的交易筛选通过点击切换；从交易结果区域左右滑动时进入全局页面导航，不改变交易筛选。
- 总览当前持仓行进入交易页后筛选为“持仓中”；最近平仓行进入后筛选为“已平仓”，并打开对应交易详情。
- 从交易列表打开详情后按系统/浏览器返回，抽屉关闭且仍在交易列表；点击关闭也只关闭抽屉。
- 详情正文可以独立滚动；滑到底继续滑动不会移动主页面。

### 设置与视觉

- 语言和时区的触发按钮具有统一尺寸/对齐样式。
- 连接成功只显示在测试按钮内，不出现在机器人名称后。
- 新增机器人输入用户名时名称自动跟随；手动填写名称后不再被用户名覆盖。
- 删除机器人没有弹窗，确认提示在列表内；清除本机数据的提示正文水平居中。
- 提示条在短、长、窄屏文案下都不溢出，并按内容自适应宽度。
- 日志日期和时间各占一行；市场交易对名单在内部滚动，主页面不滚动。

### 质量

- 新增行为有单元或 E2E 回归覆盖，既有 149 个单测和现有 E2E 不回退。
- `npm run lint`、`npm run typecheck`、`npm test`、`npm run format:check`、`npm run build` 和相关 Playwright E2E 均通过。
- 不引入 deprecated Vue API；新增/修改的 SFC 使用 `<script setup lang="ts">`、显式 props/emits 和稳定的 `v-for` key。

## 非目标

- 不重写现有全局导航页面拖拽机制。
- 不把所有确认框都改成内联提示；需要阻断背景、收集确认文本或明确风险的操作继续使用 `ConfirmDialog`。
- 不改变 Freqtrade 数据请求、缓存、WebSocket 或机器人切换生命周期。
- 不增加第三方 UI 组件库或图标依赖。
