# 必要数据就绪与独立健康检查

- 核心组只包含持仓、持仓计数、余额与盈亏；health独立，sysinfo归系统组。前台核心与健康每秒，交易历史/市场每4秒，统计/系统每12秒。
- 连接先读取配置，随后同时启动各组；只等待核心和历史完成，之后启动轮询与推送。取消额外ping前置等待；Token仍须在使用它的WebSocket连接前取得。
- 每组尚未完成的请求由连接、轮询、手动刷新共享；已完成的组可以再次刷新，不存在全量任务合并锁。合并限定同一会话和客户端，旧响应继续校验epoch与请求代次。
- 刷新按钮状态只跟随核心与历史；refreshAll返回值继续汇总全部组。刷新token阻止旧任务清除较新的状态。
- 核心与历史有效性、快照状态、在线状态及权限确认继续限制写操作。健康网络失败不清除核心就绪；任何组401仍优先处理并停止轮询、关闭推送。
- 心跳告警在健康请求完成后评估，避免休眠恢复时先检查旧缓存导致误报；后台仍只按原条件低频检查健康。
- 验收覆盖慢健康/系统/统计下完成连接、开始核心轮询与推送、快速组重刷、在途组不重复或取消、晚到401、旧任务清理、会话切换及后台告警。

本规格替代independent-refresh规格中将心跳纳入核心就绪、等待所有组才完成连接及全量刷新合并的部分。
